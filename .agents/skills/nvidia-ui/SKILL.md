# NVIDIA-inspired service UI

당일 미션이 달라도 재사용할 데스크톱 서비스 UI 기준이다. 독립 디자인이며 NVIDIA 공식 제품 인증이 아니다.

## 먼저 읽기

1. [확정값과 적용 조건](../../../docs/design/design-decisions.json)의 `decisions`를 따른다. 이 파일이 사용자 선택의 원본이다.
2. [토큰](assets/tokens.css)과 [공통 컴포넌트 CSS](assets/components.css)를 사용한다. 숫자를 다른 값으로 재정의하기 전에 원본을 확인한다.
3. 상태 표현과 빠른 확인은 [quality.md](references/quality.md), 미확정 범위는 [디자인 안내](../../../docs/design/README.md)를 따른다.

## 범위와 선택 원칙

- 실제 서비스의 입력·판단·도구 실행·검증·결과·근거를 이해하기 쉽게 만든다. 작업형/대시보드형/발표형을 먼저 고르게 하지 않는다.
- 데스크톱 전용이다. 모바일·태블릿 배치와 검사는 범위에서 제외한다. 화면 구조·도메인 기능은 당일 미션에 맞추며 예선 HER2·3D 기능을 필수로 가져오지 않는다.
- 디자인 준비는 확정·정리했다. 80개 세부 기준과 상태 표시 묶음을 재사용하며 색상·간격의 미세 비교를 다시 시작하지 않는다. 사소한 미정값은 미정으로 구분하고 실제 구현에 필요할 때만 검토한다.
- 앞으로 새 제안이 생겨도 미리보기 조작만으로 `decisions`에 옮기지 않는다. `unresolved`는 향후 구현에 필요한 경우에만 검토한다.
- 사용자는 가능한 NVIDIA 공식 사이트에 가까운 느낌을 선호한다. 새로 중요한 선택을 물을 때 공식 구현 → 예선 구현 → 서비스에 맞는 추천을 함께 제시한다. 같은 버전의 최근 검증 근거는 재사용할 수 있다.
- [출처](references/tokens.md)의 CSS 기본값·실제 계산 스타일·미확인을 구분한다. 한 사례를 사이트 전체 규칙으로 일반화하지 않는다. 공식과 달라도 한국어 가독성·상태 구분·작업 밀도에 유리하면 이유를 설명한다.

## 적용 조건

| 대상 | 조건 |
|---|---|
| 작은 카드 | 설명→입력 20px, 입력→버튼 20px |
| 복잡한 입력폼 | 설명→폼 32px; 최종 제출은 앞 영역과 32px + 1px 구분선 + 선 아래 24px |
| 일반 카드 배치 | 가로 30px, 세로 32px; 밀집 목록·홍보 목록에는 자동 적용하지 않음 |
| 한글 카드 설명 | keep-all; 긴 연속 문자열은 anywhere로 넘침 방지 |
| 파일명·식별자 | 전체 줄바꿈; 기본적으로 말줄임하지 않음 |
| 표 | 일반 본문 td와 열 헤더 thead th 기준; 그룹 헤더·행 제목은 별도 |
| 상태·테마 | 밝은 배경에서 정한 색을 다크 테마에 자동 적용하지 않음 |

## 구현

기존 프레임워크를 유지하며 의미 토큰과 공통 클래스를 연결한다. `components.css`는 `.nv-ui` 내부에서만 적용된다. 확정한 상태 팔레트는 `--state-*-color`, 상태 적용은 `[data-state]`와 `.nv-status`를 사용한다. 상태 이름·아이콘·행동 계약은 `decisions["state.presentation"]`을 따른다.

선택한 결과·근거는 같은 식별자를 가리켜야 한다. 관측 상태에 따라 도구 선택이 바뀌는 구조를 유지한다. 결과·형식·근거·종료 조건을 검증하기 전에는 완료로 표시하지 않는다. 실행 실패와 자료 부족에 따른 보류를 구분한다.

`mock/replay/live`를 표시하고 가상 데이터는 예시로 밝힌다. 진행 상태는 실제 단계와 확인 가능한 시간만 보여주며 추정 백분율이나 없는 수치를 만들지 않는다. 내부 추론 전문 대신 간결한 도구 선택 이유를 보여준다.

## 실행 과정 시각화 재사용

도구 선택·재시도·검증·보류는 [agent-flow.mjs](assets/agent-flow.mjs)와 [agent-flow.css](assets/agent-flow.css)를 재사용한다. [사용법](../../../docs/design/agent-flow.md)의 서비스 계약과 fixture로 먼저 화면을 연결한다. 기존 확정 토큰을 유지하고 컴포넌트 기본 배치를 새로운 사용자 확정값으로 승격하지 않는다. 예시 재생과 실제 실행, 화면 재생 일시정지와 실행 취소를 구분한다.

## 확인과 전달

[대표 화면](../../../design/playground.html)에서 확정 컴포넌트와 상태를 한 번에 확인한다. 이 예시는 서비스 주제·배치의 확정이 아니다. 데스크톱에서 상태 전환·긴 문구·키보드·초점·비활성을 확인하고 코드 연결 검증과 시각 검증을 구분한다.

폰트 최종 선택은 미정이다. SUIT가 실제 제공되면 사용할 수 있고, 없으면 시스템 글꼴로 표시되므로 실제 사용 환경에서 굵기와 줄바꿈을 확인한다. 공식 폰트·로고·배너를 복제하거나 폰트를 설치하지 않는다.

디자인 작업이 끝나도 승인된 에이전트 루브릭·CI 원칙·스케줄·개인별 담당을 변경하지 않는다. 요청 없이 커밋·push·배포하거나 별도 완료 보고서를 만들지 않는다.
