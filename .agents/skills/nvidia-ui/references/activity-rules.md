# 실행 지도 시각 규칙 — activity-v1

원형·색상·경로·움직임은 입력 데이터에 대응한다. 런타임 값은 [ACTIVITY_RULES](../assets/agent-flow.mjs)가 원본이며 화면 배치는 기능 기본값이다. 확정 디자인 토큰을 변경하지 않는다.

## 입력 → 패턴

| 입력 | 자동 적용 패턴 | 불변 조건 |
|---|---|---|
| 후보 구분 없는 run | 중앙 에이전트 1개 + tools의 각 도구 1개 | 노드 테두리만, 후보 링 0개 |
| candidates 1~4개 | 중앙과 모든 도구에 후보당 링 1개, 도구마다 공유 경로 1개 | 중앙/모든 도구의 링 수가 후보 수와 동일 |
| tools 2개 | 좌우 대칭 배치·짧은 높이 | 도구 등록 순서대로 배치 |
| tools 3~6개 | 동일한 타원 위 균등 배치 | 도구 수에 따라 각도 자동 계산 |
| 후보 ID | ID 정렬 순서로 번호·색·링 반경 지정 | 한 실행 안에서 후보 등록 집합 고정; 배열 재정렬로 색/위치가 바뀌지 않음 |
| 이벤트 없음 | 흐린 경로·링 + 입력 전/미선택 | 미래 기록으로 활성화하지 않음 |
| decision + tool | 해당 후보의 경로와 링 강조 | 아직 이동 없음 |
| tool running + 재생 중 | 해당 후보의 에이전트→도구 신호 | 실제 호출 시작 이벤트 필요 |
| 응답·검증·실패·종료 | 즉시 이동 정지, 텍스트와 관측 상태 갱신 | 복귀 애니메이션·장식 파동 없음 |

후보 색은 신원 구분용이며 성공/실패 색이 아니다. 예선 후보 팔레트를 재사용한 기본값이고 새 사용자 확정값은 아니다. 상태는 범례의 상태 문구, 실패의 끊긴 링, 활성도와 함께 전달한다. 미선택 링도 같은 자리에 남겨 후보 번호와 반경 대응을 유지한다.

## 형태·반복 규칙

- 노드 본체: 에이전트 반경 64, 도구 반경 34. 모두 단일 테두리이며 장식 궤도를 추가하지 않는다.
- 후보 링: 본체 반경 + 8 + 후보 인덱스 × 7. 에이전트와 도구에 같은 수식을 적용한다. 안쪽부터 범례 순서다.
- 경로: 본체 테두리부터 도구 테두리까지 연결한다. 후보 수와 관계없이 도구마다 경로는 하나다. 순차 실행에서 현재 후보의 번호·색을 범례와 맞추며 그 후보의 신호만 이동한다.
- 도구 아이콘: 도구의 역할을 나타내고 상태나 후보를 뜻하지 않는다. 등록하지 않은 도구는 공통 도구 아이콘을 사용한다.
- 이유: 지도 바로 아래 같은 위치에 유지한다. 긴 내용 때문에 지도가 이동하거나 크기가 변하지 않도록 한다.

## 모션·상태 전환

신호는 길이 12%의 한 조각이며 2.2초 ease-in-out으로 이동한다. 시작·끝에서 투명해져 반복 경계의 튀는 느낌을 줄인다. 속도는 진행률·실제 소요 시간이 아니다. 경로/노드 강조만 240ms 전환한다. 응답은 이동 없이 상태 문구로 표시한다.

같은 실행에서는 SVG 노드를 유지하고 상태만 갱신한다. 단계 선택·같은 상태 재전달로 모션이 재시작되지 않는다. 호출 상태를 벗어나거나 재생을 정지하면 신호를 즉시 숨긴다. 새 실행 ID/후보 집합/도구 목록 변경은 지도를 재생성한다. reduced-motion은 이동과 전환을 없애고 정적 강조·텍스트를 유지한다.

## 연결 계약·범위

`renderActivity(root, run, count, {tools, playing, candidates})`를 사용한다. 후보가 없으면 candidates를 생략한다. 후보가 있으면 각각 `{id, label, run, count}`를 전달하며 각 후보의 독립된 관측 기록과 노출 개수를 사용한다. 후보 ID는 중복될 수 없다. 호출자는 실행 동안 고정된 후보 목록을 전달한다. 결과 렌더러는 별도다.

현재 기본 배치는 후보 최대 4개·도구 2~6개다. 더 많으면 집계/목록 패턴을 먼저 정의하고 검증해야 하며 작은 원을 무한 추가하지 않는다. 실시간 전송·후보 실행 스케줄러는 구현하지 않았다. 미리보기의 후보 비교는 첫 후보의 전체 기록을 끝낸 뒤 두 번째 후보의 기록을 재생한다. 실제 실행 스케줄러는 아니다. 동시에 활성인 후보 기록이 들어오면 계약 확인 문구를 표시하고 이동 신호를 중단한다.

## 검증

후보 없음/1개/2개/4개에서 모든 노드의 후보 링 수를 확인한다. 후보 배열 순서를 바꿔도 ID별 색/반경이 유지되는지 확인한다. 한 후보가 끝난 뒤 다음 후보가 도구를 호출하는 순차 처리, 실패/재시도, 정지/초기화, reduced-motion을 확인한다. 형태만 보고 실제 도구 실행이나 사용자 품질 승인을 주장하지 않는다.
