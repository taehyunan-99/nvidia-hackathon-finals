# 확정 상태 표시와 빠른 확인

## 상태 표시 묶음 — 사용자 확정

| 상태 | 표시 | 다음 행동 |
|---|---|---|
| 입력 전 | 회색 ○ + 입력 안내 | 예시 또는 실제 입력 제공 |
| 진행 중 | 녹색 … + 관측된 단계 | 지원되는 경우 중단; 추정 백분율 금지 |
| 완료 | 녹색 ✓ + 검증된 범위 | 결과와 출처 확인 |
| 보류 | 황갈색 ! + 부족한 자료 | 확인된 결과 유지, 추가 자료 요청 |
| 실패 | 빨강 × + 실패 이유 | 실제 지원되는 재시도·대안 |

원본은 docs/design/design-decisions.json의 decisions["state.presentation"]이다. 사용자가 의미·색·아이콘·다음 행동을 한 묶음으로 확정했다. 세부 색 질문을 재개하지 않는다.

공식 홈페이지의 녹색 강조·중립색 표현은 기존 출처를 참고했다. NVIDIA의 다섯 단계 에이전트 상태 규격을 확인한 것은 아니다. 예선 tokens.css는 success #5B9A6F / warning #C4955A / error #C45B5B를 구분한다. 확정한 안은 선택한 녹색·얇은 테두리를 유지하고 흰 바탕에서 문구가 잘 읽히도록 더 짙은 보류·실패 색을 사용한다.

근거: [NVIDIA 공식](https://www.nvidia.com/ko-kr/) · [예선 상태 색](https://github.com/taehyunan-99/nvidia-hackathon/blob/52f6be29e432b1fa660e2a9b3b6b7556d04793d4/frontend/src/tokens.css#L28) · [에이전트 흐름](../../../../docs/playbooks/agent-flow.md).

## 확인

- 대표 데스크톱 화면에서 5개 상태와 긴 파일명·설명·표를 확인한다. 모바일·태블릿 검사는 제외한다.
- 입력→진행→결과·근거의 연결, 보류 시 부분 결과 보존, 실패 시 성공 결과 제거를 확인한다.
- Tab/Enter/초점 표시/입력 label/비활성 버튼을 확인한다. 상태를 색에만 의존하지 않고 role=status로 알린다.
- 일반 텍스트 대비 4.5:1, 큰 글자 3:1을 목표로 한다. 비활성·장식 색은 별도 평가하며 전체 접근성 인증으로 표현하지 않는다.
- 긴 문자열은 전체 표시하되 표 내부 스크롤을 허용한다. 페이지 전체의 불필요한 수평 넘침은 없게 한다.
- reduced-motion에서 버튼 전환을 생략한다. 실제 제공되지 않은 폰트·굵기를 제공된 것으로 가정하지 않는다.
- 실제 API 실행과 시각 미리보기 검증을 구분한다. 처음 보는 팀원의 사용 검증은 팀원이 수행하기 전까지 완료로 표시하지 않는다.
