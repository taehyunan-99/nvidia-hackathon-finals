# 팀원·GitHub 준비 규칙

본선의 주 메뉴에 팀원과 GitHub 진입을 재사용한다. [준비 데이터](../assets/team-content.json)가 콘텐츠 원본이며, 작업 내용과 주소는 당일 채운다. 지금은 데이터·구현 규칙 준비이며 새 본선 사이트나 탭 구현 완료를 뜻하지 않는다.

## 확정 범위와 출처

2026-10-05 사용자 요청: 예선 팀에서 김희태를 제외한 안태현·조수빈 두 명으로 구성한다. 이름·계정명·프로필 이미지 주소는 예선 로컬 소스의 기존 값을 옮겼다. 최신 외부 프로필의 유효성은 확인하지 않았다. 학교·직책·소개·본선 역할은 추정하지 않는다.

예선 `frontend/src/AgentStart.tsx`의 Team은 프로필 카드와 프로젝트 GitHub 링크로 구성된다. `main.tsx`의 주 메뉴는 분석/소개/팀이며 GitHub는 별도 내부 페이지가 아니라 팀 화면의 외부 링크다. 본선에서는 사용자 요청대로 주 메뉴에도 GitHub 진입을 준비하되 빈 내부 GitHub 페이지를 새로 만들지 않는다. 원본 revision과 파일 경로는 데이터의 source에 보존한다.

## 데이터 → 화면 규칙

| 입력 | 화면 | 비어 있을 때 |
|---|---|---|
| team.members | 배열 순서로 동일 크기의 2열 카드, 01/02 표시 | 현재 두 명만 사용; 예선 세 번째 카드/빈 자리는 만들지 않음 |
| name, handle | 이름을 제목, 계정명은 보조 텍스트 | 이름·ID는 필수; URL을 계정명에서 자동 생성하지 않음 |
| avatar_url | 예선처럼 88px 원형 프로필, 이름을 대체 텍스트로 제공 | 로드 실패/오프라인 시 같은 크기의 이름 첫 글자 표시 |
| role, contribution | 역할 한 줄, 실제 담당 작업 설명 | 요소 자체를 생략; 예선 역할/작업을 본선 기여로 이월하지 않음 |
| profile_url | 카드 하단 개인 GitHub 외부 링크 | 계정명 텍스트만 표시, 가짜 링크/빈 버튼 없음 |
| github.repository_url | 주 메뉴 GitHub와 팀 하단 프로젝트 GitHub 버튼에 같은 주소 연결 | 준비 화면은 `GitHub · 주소 준비 중` 비활성 항목; 팀 하단은 준비 중 문구 |
| team.description, github.description | 해당 제목 아래 설명 | 생략; 임의의 프로젝트 이름·성과를 채우지 않음 |

팀 페이지 제목은 `팀원 소개`, 저장소 영역 제목은 `프로젝트 코드와 개발 기록`을 기본으로 둔다. Bio-3·HER2·세 사람·예선 배포/기여 문구는 복사하지 않는다. 김희태의 카드·계정·이미지는 데이터에 넣지 않는다.

## 디자인·동작 패턴

- 예선의 프로필 → 역할/이름/설명 → 개인 링크 → 프로젝트 저장소 영역 순서를 유지한다. 내용이 없는 역할·설명은 자연스럽게 접고 카드 높이는 같은 행에서 맞춘다.
- 2명은 같은 폭의 2열이다. 간격·패딩·테두리·텍스트·버튼은 확정된 tokens.css와 components.css를 사용한다. 예선의 3열/16px 간격/4px 장식 테두리를 그대로 복사해 확정 토큰과 충돌시키지 않는다. 프로필 88px는 예선 재사용 기본값이며 새 사용자 확정 토큰은 아니다.
- `팀원`은 내부 화면 전환이다. 기존 프레임워크의 내비게이션 방식에 맞추고 현재 항목을 aria-current로 표시한다. 분석 실행 상태를 지우거나 새 실행을 시작하지 않는다.
- `GitHub`는 주소가 있을 때 외부 링크와 ↗를 표시하고 새 탭으로 연다. target=_blank와 rel=noopener noreferrer를 사용한다. 주소가 없으면 href를 만들지 않고 aria-disabled 및 준비 중 문구를 제공한다.
- 내부 팀원 메뉴와 외부 GitHub 링크를 같은 ARIA tablist에 억지로 넣지 않는다. 주 메뉴는 nav이며 실제 동작에 맞는 링크/버튼을 사용한다.
- 이 화면에는 실행 신호·후보 링·반복 모션을 적용하지 않는다. 프로필 원형은 인물 이미지 프레임이고 후보 상태 링과 다른 패턴이다. Tab 초점·링크 hover는 기존 컴포넌트 규칙을 사용한다.

## 당일 구현 순서

1. team-content.json을 읽어 두 명의 이름·계정·이미지를 연결한다. 본선 역할/실제 작업과 설명을 채운다. 개인 링크도 당일 확인한 값만 profile_url에 넣는다.
2. 본선 저장소의 실제 주소를 repository_url 한 곳에 채우고, 주 메뉴와 팀 하단에서 같은 값을 읽는다. 예선 저장소 URL을 기본 연결로 쓰지 않는다.
3. 기존 서비스의 주 메뉴에 팀원·GitHub를 연결하고 위 카드/빈 값 규칙을 적용한다. 프로필 이미지 실패·주소 미입력·주소 입력·분석 화면 왕복을 확인한다.

완료 확인: 팀원은 정확히 두 명, 미입력 역할/작업은 미노출, 주소 없는 GitHub는 클릭 불가, 입력 후 두 저장소 링크 일치, 키보드 초점 정상, 분석 실행 보존. 실제 URL 접근성과 프로필 이미지 표시는 당일 연결 후 확인한다.
