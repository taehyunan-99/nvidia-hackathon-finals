# 가족 문화체험 에이전트 설계

[MVP 범위](README.md)가 기능 원본이다. 아래는 구현을 위한 설계안이며 함수명·스택·배치가 구현 완료됐다는 뜻은 아니다. 기존 [공통 흐름](../playbooks/agent-flow.md), [하네스](../playbooks/harness.md), [입출력 계약](../catalog/contracts.md)을 재사용하되 research-v1 리허설을 제품 API로 그대로 간주하지 않는다.

## 최소 흐름과 책임

사용자 조건 → 자료 조회 → 조건·충돌 해석 → 추가 조회/질문/대안 선택 → 독립 검증 → 결과·근거·미확인 사항.

| 구성 | 역할 |
|---|---|
| 입력 코드 | 필요한 가족·날짜 조건, 입력 범위와 허용 행동 확인; 이름·신분증·생년월일 원문은 기본 입력으로 요구하지 않음 |
| 단일 Nemotron/NIM + NAT 에이전트 | 관측을 보고 다음 조회·질문·대안·종료를 선택; 실제 모델/endpoint·NAT 버전 연결은 검증 필요 |
| 검색·상세 도구 | 서울 예약 API와 승인된 공식 상세 문서에서 식별자·원문·수집 시점·적용 조건 반환 |
| 코드 검증기 | 날짜/회차·필수 조건·출처 식별자·도구 인자·예산·종료 조건 검사 |
| OpenShell | 실제 파일/검색/API 도구를 샌드박스 안에서 실행하고 허용 경로·통신만 통과 |
| 웹 화면 | 입력, 관측된 실행 상태, 후보와 근거, 수정·재질문 경로; mock/replay/live 구분 |

단순 날짜 필터와 산술 계산은 코드가 맡는다. 에이전트의 가치는 자유서술 조건의 의미·적용 범위 해석과 다음 확인의 선택으로 검증한다. 항상 같은 순서의 도구 호출이나 번역만으로 자율성을 주장하지 않는다.

## 도구와 상태 계약 — 제안

| 도구 역할 | 입력 | 반환·실패 구분 |
|---|---|---|
| 후보 조회 | 지역·날짜·문화 주제 | 서비스 ID와 후보 목록, 조회 시점; 빈 결과와 API 오류 구분 |
| 상세 근거 조회 | 후보 ID·허용 원문 식별자 | 대상·동반·회차·신청 조건 및 인용 위치; 누락과 충돌 보존 |
| 조건 검증 | 가족 조건 + 추출 조건·근거 | 적합/부적합/미확인 및 이유; 예약 성공 판정 아님 |
| 결과 저장 | 검증된 후보·이유·출처 | 요청별 허용 출력; 임의 경로·외부 업로드 금지 |

단계 상태는 입력 대기·조회·확인·추가 질문·완료·보류·실패로 나누는 안을 사용한다. 최종 JSON schema는 아직 미확정이며, 최소 결과에는 후보 ID, 문화 내용, 조건별 판정, 채택/제외 이유, 근거 URL/파일 위치, 수집 시각, 남은 확인, 예약 경로가 필요하다.

## 판단이 바뀌어야 하는 대표 상황

| 관측 | 다음 판단·행동 | 금지할 잘못된 완료 |
|---|---|---|
| 가족 대상이지만 특정 학년·보호자 1인 제한 | 상세 조건을 적용; 동반자가 바뀌면 재검토 | ‘가족’이라는 단어만으로 전원 참여 가능 |
| 상세 설명과 요약 대상이 충돌 | 적용 범위 확인·추가 조회·질문 또는 보류 | 항상 최신/엄격 조건을 임의 정답으로 채택 |
| 좌표가 있는 온라인 교육 | 대면 체험 요청에서는 제외·다른 후보 탐색 | 장소 방문을 안내 |
| 접수중이지만 개별 회차 정보가 없음 | 공식 확인 경로와 미확인 조건 표시 | 잔여석·예약 성공 보장 |
| 자료가 없거나 조회 실패 | 추가 근거 수집, 부분 결과, 제한된 재시도 | 없는 조건·일정 생성 |

영어/통역 서브미션을 채택한 경우에만 영어 진행·주최 측 통역 제공·참가자 통역 동반·미확인을 별도 조건으로 추가한다. 영문 화면이나 자동 번역을 현장 지원으로 해석하지 않는다.

## OpenShell과 공통 테스트

- 실제 에이전트·자료 조회·파일/API 도구는 OpenShell 경계 안에서 실행한다. 호스트 검색기가 금지 파일을 대신 읽는 우회를 만들지 않는다.
- `/hackathon/input`은 허용 읽기, `/hackathon/output`은 결과 쓰기, `restricted`·`secrets`는 금지 접근으로 검증한다. 금지 파일의 삭제·빈 파일·미마운트를 차단 증거로 쓰지 않는다.
- API/모델은 필요한 목적지·경로·요청만 허용하고 실제 effective policy를 확인한다. 원문 문서의 링크나 지시가 허용 목록을 자동 확장하지 못하게 한다.
- 예약·취소·결제·이메일·외부 업로드는 현재 허용 도구가 아니다. 시스템 접근 통제 외에 애플리케이션의 인자 검증과 요청별 소유권 검사도 필요하다.
- 모델에 보낼 입력을 최소화한다. OpenShell만으로 허용된 모델 endpoint에 전송하는 개인정보의 의미까지 자동 통제된다고 주장하지 않는다.

공통 파일을 읽는 도구와 실서비스 API 도구가 같은 근거·검증 계약을 따른다. 공통 요청에는 가족/위치 정보를 임의로 추가하지 않고 파일 속 가상 지명을 실장소 API에 맞춰 변경하지 않는다.

버전별 정책과 설치는 [보안정책 조사](../catalog/tools/openshell-security.md), [Brev 준비](../playbooks/brev-openshell-setup.md), [AWS–Brev 연결](../playbooks/aws-brev-deployment.md)을 따른다. 문서 조사 버전과 설치 버전이 다르면 실행 계약부터 맞춘다.

## 스킬·확장·검증

`nat-agent-configuration`, `nat-tools-and-functions`로 최소 도구를 연결한다. Retriever/MCP·다중 에이전트는 자료량이나 연결 필요가 확인될 때만 추가한다. 스킬은 개발 지침이며 설치만으로 런타임 함수가 생기지 않는다.

`nvidia-ui`와 기존 상태 컴포넌트를 재사용하고, `agent-rubric`·`frontend-rubric`·`submission-check`는 각각 실제 판단, 화면, 필수 경계를 확인한다. 선정 기준은 [topic-v1](../evaluation/topic-selection.md)이며 구현 점수와 합산하지 않는다.

[모델 호출 정책](../playbooks/model-policy.md)과 JSON을 런타임에서 강제한다: 실행당 실제 요청 40회·일일 4,000회·요청 간격 15초·출력 1,024토큰·10단계, 재시도 포함. 3~4회 모델 요청도 간격만 30~45초가 될 수 있으므로 한 번의 짧은 완주와 변경 입력으로 지연을 측정한다.

정상·가족 조건 변경·근거 충돌·자료 부족·API 실패·문서 내 공격 지시를 비교하고 잘못된 완료와 과도한 보류를 따로 측정한다. 구현 전 사람 검토로 허용 결론과 금지 단정을 정하고, 모델이 자기 답을 정답표로 만들지 않게 한다.
