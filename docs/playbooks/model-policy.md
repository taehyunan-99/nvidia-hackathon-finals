# 모델 호출 운영 기준

본선에서도 예선의 여유 있는 호출 기준을 유지한다. 실행 설정 원본은 [model-policy.json](model-policy.json), 실제 요청 제어는 [model_policy.py](../../scripts/model_policy.py)다. 도구 이름·도메인에 관계없이 모델 호출을 이 제어 경계에 연결한다.

| 항목 | 본선 기본값 | 근거 |
|---|---:|---|
| 한 실행의 실제 HTTP 요청 | 40회 | 예선 `logic/call_budget.py`, `.env.aws.example` |
| 하루 실제 HTTP 요청 | 4,000회 | 동일 예선 파일; 한국 시간 자정 기준 |
| 요청 시작 간격 | 최소 15초 | 예선 `logic/nat_workflow.yml`, `logic/nat_model.py` |
| 응답 출력 상한 | 1,024토큰 | 예선 NAT 설정 |
| 에이전트 판단 단계 | 최대 10단계 | 예선 NAT `max_iterations` |
| HTTP 429 시도 | 최초 포함 최대 3회 | 예선 `logic/nat_model.py` |
| 429 대기 | 30초·60초 기준, Retry-After 존중, 최대 120초 | 예선 복구 규칙; 서버 요구가 120초를 넘으면 재시도하지 않음 |
| 한 요청 timeout | 60초 | 예선 `logic/agent.py`의 판단 timeout 재사용 |
| 한 실행의 시간 상한 | 900초(15분) | 본선 추가 기본값; 종전 점검용 180초를 대체, 예선의 확정 수치로 표현하지 않음 |

40회는 도구 개수나 판단 단계 수가 아니라 **재시도 포함 실제 전송 횟수**다. 모델 호출 상한을 늘려도 검증 전 완료·허용되지 않은 도구·불필요한 반복 호출을 성공으로 허용하지 않는다. 상한 도달은 미완료/보류로 처리하며 정상 완료로 표시하지 않는다. 공식 계정 쿼터·크레딧을 위의 애플리케이션 한도와 동일하게 해석하지 않는다.

## 현재 적용 경로

`probe_research.py`는 로컬 `.env`/프로세스 환경의 명시적 설정을 우선하고, 없으면 위 JSON을 읽는다. 정상·자료 부족 각각을 한 실행으로 취급하며 실행 사이에도 요청 간격과 일일 누적은 유지한다. `--case both`는 실행 두 건이므로 최대 80회이지만 일일 상한도 함께 적용된다. 기본은 dry-run이며 설정 조회는 모델 호출·장부 생성을 하지 않는다.

실제 전송 직전에 SQLite 트랜잭션으로 일일 횟수를 예약한다. 실패·429 재시도도 포함하며 `runs/model-daily-budget.sqlite3`에 저장한다. 재시작해도 그날 횟수는 유지되고 자정 이후 새 날짜로 집계한다. `MODEL_DAILY_BUDGET_PATH`로 같은 장부를 사용하는 프로세스는 일일 횟수를 공유한다. 다른 노트북의 별도 파일은 자동 합산되지 않으며 기본 15초 간격은 같은 Budget 인스턴스를 쓰는 단일 호출 경로에 적용된다.

새 서비스/worker는 `load_policy(settings)`와 `Budget(send, policy=..., daily_path=...)`를 재사용하고 요청 timeout·출력 토큰·에이전트 단계에도 같은 값을 전달한다. SDK 자체의 숨은 재시도는 끄거나 실제 시도마다 이 제어 경계를 통과시킨다. worker를 늘리면 호출 간격도 공유 제어로 바꿔야 한다. 새 실행은 `Budget.start_run()`으로 실행 횟수만 초기화하며 일일 장부는 지우지 않는다.

[NAT 예제](examples/nat/workflow.yml)는 출력 토큰·판단 단계만 반영한다. 기본 `nim` provider가 JSON의 물리 요청 제한까지 자동 적용하지는 않으므로 실제 NAT 서비스를 만들 때 provider adapter를 연결하고 테스트해야 한다. 덧셈 연결 점검용 `probe_nim.py`의 고정 두 요청은 작은 진단용 예외이며 본선 서비스 기본값이 아니다.

## 변경·검증

한도를 바꿀 때 JSON과 관련 환경 예시·런타임 연결을 함께 확인한다. CI의 '10분 대기 후 검증 불충분/대체 확인' 원칙과 모델 실행 15분 상한은 서로 다른 기준이다. 검사에는 임시 장부·가짜 시계를 사용하며 실모델 호출은 포함하지 않는다.

[호출 정책 테스트](../../scripts/test_model_policy.py)는 실행/일일 상한·한국 날짜 변경·호출 간격·429 시도 횟수·Retry-After·시간 상한을 확인한다. 한도 변경 검사는 모델 판단의 타당성이나 이전 리허설의 통과를 의미하지 않는다.
