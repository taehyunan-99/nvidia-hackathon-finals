# 도구 선택·분석 과정 화면

[실행 화면](../../design/agent-flow.html) · [입출력 계약](../catalog/contracts.md) · [로컬 실행](../playbooks/rehearsal.md)

확정된 80개 디자인 기준과 상태 팔레트를 재사용한다. 아래 실행 흐름 컴포넌트는 이번 기능 구현의 기본 배치이며 새로운 색상·간격·페이지 구조를 사용자 확정값으로 추가하지 않는다. 모바일·배포는 범위에서 제외한다.

## 재사용 파일

- [agent-flow.mjs](../../.agents/skills/nvidia-ui/assets/agent-flow.mjs): 실행 경로·선택 이유·근거·결과 렌더링.
- [agent-flow.css](../../.agents/skills/nvidia-ui/assets/agent-flow.css): 기존 토큰을 사용하는 단계 카드·선택·근거 배치.
- [화면 연결 예시](../../design/agent-flow.mjs): fixture 로딩·예시 재생·단계 선택.

`tokens.css → components.css → agent-flow.css` 순서로 불러온다. `renderFlow(root, run, visibleCount, selectedSeq, onSelect)`의 반환값을 `renderResult(root, run, view)`에 전달한다. 화면 데이터만 바꾸면 같은 컴포넌트로 기존 근거 재사용·추가 조사·재시도·보류를 보여준다. 미션별 결과 영역은 해당 artifact schema에 맞춰 바꾼다.

## 시각 요소의 의미

| 요소 | 표시 기준 |
|---|---|
| 순서가 있는 단계 카드 | 실제 event의 seq·유형·당시 상태; 호출 시작 기록과 현재 실행 상태를 구분 |
| 판단 카드 | 선택한 도구와 짧은 이유; 내부 추론 전문은 표시하지 않음 |
| 도구 카드 | 호출 시작/반환·시도 횟수·오류; 재시도는 별도 이벤트 |
| 검증 카드 | 근거 부족·충돌·형식 검사 결과; 도구 성공과 업무 완료 구분 |
| 근거·결과 영역 | 현재까지 노출된 evidence ID만 표시; 최종 검증 전 산출물 숨김 |

입력 전은 회색, 진행/완료는 녹색, 보류는 황갈색, 실패는 빨강이며 아이콘·설명·다음 행동을 함께 제공한다. 보류와 실패는 기존 근거를 유지하지만 확정 결론을 만들지 않는다. 단계 카드는 키보드로 선택할 수 있고 선택 이유/근거가 함께 바뀐다.

## 확인 경계

기본 화면은 합성 JSON의 **예시 재생**이다. `?source=live`는 로컬 probe가 저장한 실모델 실행 기록을 읽으며 LIVE 모델과 합성 도구를 구분한다. 저장된 기록이 없으면 로딩 실패로 표시하고 mock으로 대체하지 않는다. 재생 속도·표시 이벤트 수는 실제 실행 시간·작업 완료율이 아니다. 재생 일시정지는 실행 취소가 아니며, 새 case를 고르거나 처음으로 돌아가면 이전 타이머와 표시 결과를 지운다. 실제 서비스로 옮길 때는 현재 실행만 렌더링하고 인증 정보·모델 원문을 제외한 검증된 이벤트를 전달한다.

폰트 제공 방식·최종 페이지 구조·표 장식·다크 테마는 기존 미정 상태를 유지한다. 새 팀원의 설명 없는 사용 시험, live 이벤트 연결과 실제 응답 지연은 별도 확인 대상이다.

## 당일 연결 순서

1. 미션에서 실제 사용 가능한 도구만 `{도구ID: 짧은 표시 이름}`으로 정의하고 `renderActivity(root, run, visibleCount, {tools, playing})`에 전달한다. 중앙 AGENT와 주변 도구 지도를 재사용한다. 기본 배치는 2~6개 도구·짧은 이름에 맞춘다. 그 이상이거나 긴 이름이면 목록 배치로 바꾸고 다시 확인한다.
2. 서비스 adapter가 검증한 `decision/tool/validation/result` 이벤트를 연결한다. 판단 이유는 짧은 공개 설명만, `tool`에는 도구 ID·시도 횟수·상태를 넣는다. 이름을 바꿔도 도구 ID는 이벤트와 일치해야 한다. 모델 선택·규칙 선택·코드 종료는 실제 주체를 label/reason에 유지한다.
3. 아래 모션 규칙과 기존 `renderFlow`의 키보드 단계 탐색을 함께 사용한다. `renderResult`는 research-v1 전용이므로 다른 미션에서는 mission-v1의 해당 artifact용 결과 렌더러를 연결한다. 공통 지도는 도메인 산출물을 읽지 않는다.
4. 정상·추가 선택·재시도·보류·실패 합성 입력으로 먼저 연결하고 실제 이벤트 수신을 별도로 검사한다. 현재 미리보기는 외부 호출이 없는 기록 재생이다.

## 직관성과 모션 품질의 완료 기준

2026-10-05 사용자 확인: 도구 선택 모션은 현재 수준으로 충분하며 다음 준비는 팀원·GitHub 영역이다. 추가 미세 모션 비교를 재개하지 않는다. 실제 실행 연결은 별도 확인 대상이다.

2026-10-05 사용자 우선순위는 실제 선택·사용을 한눈에 이해하는 직관성과 이를 표현하는 애니메이션 품질이다. 선택 도구와 선택 이유를 함께 노출하고, 호출 전 강조·실행 중 바깥 방향 신호·응답의 정적 상태가 혼동되지 않아야 한다. 이동에는 완급과 나타남/사라짐을 주고, 후보 수와 무관한 장식 링·파동은 사용하지 않는다. 장식 때문에 상태나 결과 노출을 늦추지 않는다.

브라우저에서 형태·상태·중단·모션 감소를 확인하는 것과 사용자가 직관적이고 만족스럽다고 평가하는 것은 구분한다. 현재 구현은 기능 미리보기이며 사용자 시각 품질 승인과 실제 실행 연결은 별도다.

## 이벤트와 모션 규격

예선 `frontend/src/AgentActivity.tsx`와 `agent-activity.css`의 후보 ID별 링·경로·범례 대응과 활성 호출 경로를 재사용 원리로 삼았다. 후보별 표현은 명시적인 후보 데이터가 있을 때만 적용한다. HER2 도구 이름·3D 기능은 가져오지 않는다. [시각 규칙 원본](../../.agents/skills/nvidia-ui/references/activity-rules.md)에 입력→패턴, 형태, 전환, 범위와 검증 기준을 정의한다.

| 관측 | 지도와 전환 | 중단 규칙 |
|---|---|---|
| 실행 전·미선택 | 회색 도구와 정적인 연결선; 미선택 문구 | 미래 이벤트로 선택/호출 여부를 미리 표시하지 않음 |
| decision + tool | 선택 경로와 도구 테두리를 즉시 강조; 호출 전 문구·이유 | 신호 모션 없음; 선택만으로 호출했다고 표현하지 않음 |
| tool running | 에이전트→도구 경계 사이 신호 2.2초 주기, 시작/끝 페이드; 호출 중·시도 표시 | 다음 이벤트·일시정지·새 실행·종료 즉시 제거 |
| tool completed | 모션 없이 응답 수신 표시 | 업무 완료와 구분; 응답 이벤트를 벗어나면 제거 |
| tool failed | 빨강·× 호출 실패·오류 설명; 모션 없음 | 실패를 지속 실행으로 표현하지 않음 |
| 재시도/다른 도구 선택 | 새 판단에서 해당 경로로 즉시 전환; 이전 관측 상태 유지 | 재시도는 실제 attempt 기준; 임의 반복 금지 |
| validation | 중앙 근거 검증 + 기존 카드의 통과/보류 이유 | 다음 호출을 예측해서 선을 움직이지 않음 |
| 코드 종료·최종 결과 | 코드 종료 문구 후 검증 후 완료/보류/실패; 정적 지도 | 종료 시 모든 신호 제거, 부분 근거는 유지 |

모션 시간은 표시 효과이며 실제 소요 시간이나 완료율이 아니다. 미리보기 `playing`은 기록 재생 여부다. live 전송에서는 별도 연결 상태를 표시하고 연결이 끊기거나 사용자 정지 시 모션을 멈춘다. 이벤트가 없는 시간을 추정 진행률로 채우지 않는다.

## 접근성·실행 정리

- `prefers-reduced-motion: reduce`는 이동 신호와 강조 전환을 제거하며 선택 경로·문구는 유지한다. 색 없이도 미선택/호출 전/호출 중/응답/실패·시도를 구분한다.
- 지도는 설명용 이미지이며 조작은 기존 단계 버튼으로 한다. Tab/Enter로 선택 이유·근거를 탐색하고 새 이벤트 렌더링에서 기존 단계 초점을 보존한다. 상태 알림은 페이지의 단일 `role=status`를 사용한다.
- 과거 카드를 선택해도 지도는 가장 최근 관측 상태를 유지한다. 선택 이유 탐색만으로 신호 애니메이션이 다시 시작되지 않는다.
- 새 예시·처음으로는 재생 타이머, 도구 강조, 선택 이유, 결과를 초기화한다. 같은 root에 새 실행을 연결할 때 run_id를 바꾸고 count=0부터 시작한다. 컴포넌트 자체는 타이머를 생성하지 않는다.
- 실시간 adapter는 실행 ID·순번으로 중복/역순/이전 실행을 걸러야 한다. 이는 현재 저장 기록 미리보기의 구현 범위를 벗어나므로 당일 통합 검증에 포함한다.

실제 검색 서비스·GPU 연결, 화면에서 실제 모델을 요청하는 새 서비스, 팀원 사용 시험은 이번 시각 설계의 확인 범위에 포함하지 않는다.
