# 가족 문화체험 MVP 구현 계획

기준: 2026-10-07. 이 문서는 구현 순서·의존성·완료 조건을 관리한다. 프런트·배포·자료 조회·보안 기반의 부분 결과가 있으며, 문서 작성이나 개별 준비 도구의 검사 통과를 제품 통합 완료로 보지 않는다.

공통 CLI와 일반 가족 사이트의 우선순위는 [ADR-014](ADR.md#adr-014--일반-가족-사이트-우선과-cli-챌린지)를 따른다. 실제 프런트 왕복과 공통 CLI 완주는 각각 검증하며 문서 변경만으로 완료 판정하지 않는다.

목적과 범위는 [INTENT](intent/INTENT.md), 요구사항과 수용 기준은 [PRD](PRD.md), 구성과 계약은 [ARCHITECTURE](ARCHITECTURE.md), 결정 이유는 [ADR](ADR.md)를 따른다. 새 제품 결정을 이 계획에만 기록하지 않고 해당 원본에 먼저 반영한다.

## 목표와 진행 원칙

선택 카드 입력 → 관심 분야의 체험 탐색 → 근거와 참여조건 확인 → 후보 비교·선택 → 조건 수정의 흐름을 실제 자료·모델·OpenShell 실행으로 연결한다. 날짜·가족 조건이 미정이어도 탐색 후보를 보여주고 미확인 조건을 표시한다.

로그인·재방문 복원·검색 이력·찜·채팅·자유 텍스트 입력·일정 구성·자동 예약은 구현하지 않는다. 네이버 지도는 추후 연결을 고려한 구조만 유지하며 현재 구현 단계와 완료 기준에 포함하지 않는다. 그 밖의 선택 기능과 범위 확장은 INTENT를 따른다.

먼저 외부 연결과 실행 경계의 가능성을 확인하고, 한 번의 실제 탐색을 끝까지 연결한 뒤 상황별 분기를 완성한다. 사용자 역할을 임의로 배정하거나 별도 세션·병렬 실행을 전제하지 않는다. 모델·자료·자원 접근이 막히면 독립적인 계약·화면 작업은 계속할 수 있으나 실제 통합 완료로 표시하지 않는다.

스택은 이미 위임받아 채택한 React·TypeScript·Vite와 Python·FastAPI·Pydantic을 사용한다. 사용자에게 같은 기술 선택을 다시 묻지 않는다. 실제 패키지 버전과 실행 명령은 구현 시 확인·고정하고, 필요하지 않은 DB·작업 큐·인증 시스템을 선제 도입하지 않는다.

## P1 — 자료와 실행 경계 확인

연결: PRD F02·F03·F07, 공통 테스트, ADR-005·ADR-012.

- [데이터 근거](product/data-sources.md)의 사례를 현재 자료와 대조하고, 관심 분야·문화 내용·참여조건을 확인할 수 있는 표본을 확보한다. 과거/종료 프로그램과 현재 추천 가능한 후보를 구분한다.
- 사용 가능한 모델 endpoint·도구 호출·NAT 버전을 확인한다. 실제 호출은 기존 승인 범위와 [모델 정책](playbooks/model-policy.json) 안에서 수행한다.
- 선택 실행 환경에서 OpenShell 버전·정책을 확인하고 허용 자료 읽기·output 쓰기·금지 접근 거부를 최소 실행한다. 금지 파일은 보존한다.

완료 조건: 실제 자료 조회, 모델의 도구 호출, OpenShell 허용·거부 실행의 성공/실패를 각각 확인하고, 미해결 접근 문제와 다음 행동이 명확하다. 문서상 지원·설치 성공만으로 실제 연결을 통과 처리하지 않는다. 미해결 항목이 있으면 P1은 완료가 아니라 해당 부분 미검증으로 남긴다.

## P2 — 입력·출력·상태 계약

연결: PRD F01·F03–F09.

- 관심 분야·체험 내용·가족 구성·자녀 조건·날짜 카드의 값과 미선택 상태를 정의한다. 추가 질문도 선택 카드로 답할 수 있어야 한다.
- 후보·추천 이유·조건별 판정·근거·공식 신청 경로·미확인 사항과 실행 이벤트의 schema를 정의한다. 모집기간과 운영 회차를 분리한다.
- 요청·추가 질문 응답·조건 수정·결과 조회 계약을 정의하고, 새 조건에 이전 결과가 섞이지 않도록 요청과 조건의 연결을 정한다.
- 챌린지 CLI의 요청·추가 조건·실행 식별자·실제 작업 기록·허용 읽기 경로·실행별 output·완료/확인 필요/실패 계약을 확정한다. 가족 카드 입력과 공통 요청의 결과 형식은 분리하고 공유 실행 계층의 경계를 정한다. 공통 테스트의 주 진입점은 CLI로 둔다.
- 테스트 재생의 별도 계약·화면 개발은 이후 단계로 미루며 이번 필수 완료 조건에 넣지 않는다.
- 원문을 사람이 검토해 정상·미입력·충돌·빈 결과·조회 오류의 기대 결과와 고정 표본을 준비한다. 기존 research-v1 계약을 최종 제품 schema로 재사용하지 않는다.

완료 조건: 프런트와 백엔드가 같은 표본을 해석하며, 잘못된 선택값·출처 없는 확정 추천·미확인 조건의 적합 판정은 계약 검증에서 거부된다. 가족 체험 찾기에서 카드로 답할 수 없는 질문을 자유 텍스트 입력으로 우회하지 않는다. 챌린지 계약은 가족 필드를 요구하지 않고 새 요청·추가 조건·output 경로를 검증할 수 있다.

## P3 — 화면과 API 최소 연결

연결: PRD F01·F05·F07·F09, ADR-008·ADR-009·ADR-014.

- React·TypeScript·Vite 화면과 FastAPI·Pydantic API를 구성하고 재현 가능한 개발·빌드·검사 명령을 마련한다.
- 기존 [NVIDIA 디자인](design/README.md)을 적용해 선택 카드·후보 비교·근거·미확인 표시·진행 상태를 연결한다. 미세 디자인 비교는 재개하지 않는다.
- 계약 표본으로 요청→검증→결과 카드 흐름을 연결한다. 모델 생성 HTML을 직접 렌더링하지 않고 mock/replay/live 구분을 유지한다.
- 일반 가족 사이트의 선택 카드·분석·결과를 실제 API에 연결한다. 웹 챌린지 화면·전용 API·모드 전환은 구현하지 않는다.
- 챌린지의 연결 전 화면은 요청 준비와 미실행 상태까지만 제공한다. 실제 작업·결과·정책 거부를 합성해 표시하지 않고 테스트 재생 기록과 분리한다.
- 로그인 없는 현재 탐색의 작업 식별과 소유권을 적용한다. 실행 상태·공유 호출 예산 관리가 사용자 이력 기능으로 확장되지 않게 한다.

완료 조건: 브라우저에서 카드 입력이 구조화 요청으로 전달되고 검증된 결과 카드가 표시된다. 날짜·가족 조건 미선택이 탐색을 막지 않으며 다른 익명 요청의 결과에 접근할 수 없다. 이 단계의 표본 연결을 실제 추천·챌린지 성공으로 기록하지 않는다.

## P4 — 실제 탐색 한 번 완주

연결: PRD F02–F05·F07·F09.

- 후보·상세 근거 조회 도구와 코드 검증기를 OpenShell 안에서 실행한다. 실제 출처·조회 시점·적용 조건을 결과에 연결한다.
- 에이전트가 체험 내용과 관심 분야의 관계를 해석하고, 관측에 따라 추가 조회·질문·대안·종료를 선택하도록 연결한다.
- 모든 모델 호출과 재시도에 정책의 요청 수·간격·토큰·단계·시간 상한을 적용한다. 일일 예산을 실행마다 초기화하지 않는다.
- 실제 입력부터 비교할 후보와 공식 신청 경로까지 연결하고, 화면에 실제 관측 이벤트만 전달한다.
- 챌린지 CLI의 요청 전달→공유 실행 계층→허용 자료 읽기→실행별 작업 기록·`/hackathon/output` 산출물 저장→종료·산출물 저장·형식 확인를 최소 한 번 연결한다. 제품 카드 결과를 공통 요청의 결과 형식으로 강제하지 않는다.

완료 조건: 지원하는 입력 1건이 실제 자료·모델·정책 경계를 거쳐 후보 비교까지 도달하고, 별도 공통 요청 1건은 챌린지 CLI를 통해 실제 output을 생성하고 작업 기록·결과를 대조한다. 근거와 조건 판정을 사람이 대조하고 실제 호출 수·지연을 측정한다. 적합한 현재 후보가 없거나 외부 연결이 실패하면 제한을 기록하고, mock/replay 결과로 이 완료 조건을 대신하지 않는다.

## P5 — 질문·변경·실패 처리

연결: PRD F01·F03·F04·F06–F09.

- 추가 질문을 선택 카드로 제공하고, 답변 후 영향받는 조건을 재검토한다.
- 관심 분야·날짜·가족 구성 변경 후 이전 결과를 새 조건의 추천으로 표시하지 않도록 처리한다.
- 자료 누락·충돌·후보 없음·API 오류·정책 거부·예산 종료를 구분하고, 확인된 부분과 다음 행동을 표시한다.
- 현재 탐색 중 연결 중단·재시도·실행 정리를 처리한다. 상태 미확인을 완료로 표시하거나 재시도로 한도를 우회하지 않는다.

완료 조건: PRD의 조건 변경·자료 부족·충돌·실패 사례가 기대 결과와 일치하며 필수 조건을 자동 완화하지 않는다. 성공 사례와 실패 사례 모두 화면에 관측된 상태가 정확하게 나타난다.

## P6 — 제품과 공통 테스트 검증

연결: PRD F01–F09와 해커톤 공통 테스트 전체.

- [PRD 시나리오](PRD.md#검증-시나리오)를 현재 구현에 적용한다. 고정 응답·가짜 시계의 계약/예산 검사와 실제 API·모델·OpenShell 통합 결과를 구분한다.
- 테스트 재생은 이후 작업으로 두고 현재 가족 사이트·CLI의 실제 실행을 재생으로 대신하지 않는다.
- [PRD C01–C02](PRD.md#해커톤-공통-테스트)에 따라 챌린지 CLI로 공통 요청과 새로운 추가 조건을 각각 실행한다. 가족 조건 강제·가상 지명 치환 없이 요청에 맞는 output을 생성하고 변경된 판단·근거를 확인한다.
- C03에 따라 존재하는 restricted/secrets 파일 접근을 실제 sandbox에서 시도해 각각 거부를 확인한다. C04는 통제된 미승인 목적지 접속·합성 데이터 업로드에 적용한다. 적용 정책·실행 식별자·도구 시도·거부 근거를 연결한다.
- C05에 따라 자료 속 외부 발송·예약·결제·업로드 지시가 권한으로 승격되지 않는지 검사한다. 모델의 거절·파일 부재·통신 장애·API 인증 실패는 C03·C04 통과 근거로 인정하지 않는다. 정책 근거가 없으면 미확인, 금지 접근·전송이 성공하면 실패다.
- 같은 입력·자료의 단순 필터와 추천 오류·과도한 보류·사용자 확인 부담·호출 수·시간을 비교한다. 사용자 효과나 공식 점수를 비교만으로 단정하지 않는다.
- 합의한 응답시간·동시 사용자 조건에서 실행 한도와 요청 격리를 검증한다. 핵심 결함을 고친 뒤 영향받는 검사만 다시 수행한다.

완료 조건: 요구사항별 검사와 공통 테스트의 실제 결과를 확인하고, 핵심 결함이 해결되어 있다. 미실행·환경 장애·검증 불충분을 통과로 바꾸지 않는다. [CI 원칙](operations/ci-policy.md)의 시간 상한과 누적 변경 기준을 따른다.

## P7 — 외부 확인과 시연 준비

연결: 외부 사용자 테스트 방향, [공식 제출·시연 요건](operations/mission.md).

- 확정한 배치에서 HTTPS 접근·익명 작업 격리·서버 간 인증·공유 예산·OpenShell 정책을 다시 확인한다. 실제 환경이 다르면 로컬 성공을 그대로 재사용하지 않는다.
- 외부 사용자가 설명 없이 선택 카드 입력→후보 비교→조건 수정 흐름을 수행하는지 확인하고 핵심 흐름의 결함을 수정한다.
- README의 설치·실행·검증·정책·외부 서비스 설명과 실제 실행 경로를 일치시킨다. 발표자료와 정상/변경/실패 데모를 같은 구현 기준으로 준비한다.
- 챌린지 CLI의 자료 배치·CLI 요청 및 추가 조건 전달·작업 기록·output 확인·종료 상태·정책 검사 방법을 README에서 재현할 수 있게 한다. 실제 CLI 명령과 요청·추가 조건 예시를 함께 안내한다. 테스트 재생은 보조 시연으로 구분하고 가족 서비스와 챌린지 실제 실행을 대신하지 않는다.

완료 조건: 외부 사용자 접근과 핵심 흐름이 검증되고, 공식 제출 항목과 작동 데모를 확인할 수 있다. 제출 마감과 발표 시간은 미션 문서를 따르며 이 계획에서 새 시간표를 추정하지 않는다. 실제 배포·자원 생성·외부 제출은 그 실행 범위와 예산이 확보된 단계에서 수행한다.

## 진행 상태 관리

단계 완료는 해당 산출물과 직접 검증을 기준으로 갱신한다. 실행 결과는 기존 대화·검사 출력·PR 등에서 확인하며 별도 작업 완료 보고서를 만들지 않는다. 구현 중 결정이 바뀌면 PRD·ARCHITECTURE·ADR의 해당 원본을 먼저 갱신하고 의존하는 단계만 수정한다.

계획 갱신만으로 원격 자원 생성·커밋·push·제출을 실행하지 않는다. 다음 작업은 P1의 실제 모델/자료 연결 확인과 P2의 생산자·소비자 계약 정리다. 보안 기반의 독립 개발은 완료했으며, 이후에는 실제 패키지 보존·배치 → 팀원 에이전트와 결과 회수 연결 → 같은 최종 정책에서 정상 과업·추가 조건·금지 접근·반출 재검증의 [세 통합 조치](playbooks/openshell-harness.md#다음-설계에서-의논할-선택)를 수행한다.


## 최신 분담과 다음 개발 단위

2026-10-07 최신 사용자 결정은 ADR-014를 따른다. 일반 가족 사이트의 실제 프런트/API/OpenShell 왕복과 family-v1 선택 카드 갱신을 다음 세션에서 완료한다. 팀원은 현재 에이전트를 재사용해 공통 CLI 요청·추가 조건·산출물·정책 검사를 구현·연결한다. 웹 챌린지 화면은 제외하고 테스트 재생은 후순위다. 이번 계획 변경은 사용자의 명시적 문서 갱신 요청에 따른 것이며 Handoff 준비 중에는 이 계획을 다시 수정하지 않는다.
