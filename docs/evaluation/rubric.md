# 본선용 내부 루브릭 v1 — 100점

공식 배점을 확보하지 못한 상태에서 만든 **개발 우선순위 도구**다. 본선 온보딩 기준이 나오면 가중치를 별도 버전으로 바꾸고 과거 점수와 섞지 않는다. Bio-3에 유리하도록 생물학/3D/도구 개수 항목을 넣지 않았다.

## 채점

각 항목 0–4점. 가중 점수 = 가중치 × 등급 ÷ 4. 정수 등급을 사용한다.
공통 앵커: 0=없음/실패, 1=설계·고정 시안, 2=대표 1건/부분 증거, 3=대표+실패/변화 사례와 추적 근거, 4=아래 최고 기준 충족.
미실행은 `null`; 0점과 구분해서 미확인 가중치로 보고한다. 확인되지 않은 항목은 총점에서 보수적으로 0을 기여하지만 별도로 표시한다.

| ID | 항목 | 가중치 | 2점의 관찰 기준 | 4점의 관찰 기준 |
|---|---|---:|---|---|
| problem | 문제·미션 적합성 | 15 | 사용자/문제/산출물 명확 | 실제 입력과 수치화 가능한 완료 기준, 미션 제한 충족, 사용자 확인 |
| agency | 에이전트 판단 가치 | 20 | 실제 도구 호출과 한 분기 | 여러 입력에서 선택/재계획/종료 타당, 단순 기준선 대비 이득을 측정 |
| nvidia | NVIDIA의 실질 기여 | 15 | 핵심 경로 실제 NVIDIA 호출 | 모델·도구·스킬의 역할/버전/trace로 필수 기여 설명, 장식적 나열 없음 |
| quality | 결과 정확성·근거 | 15 | 대표 결과 독립 검산 | 고정 평가셋+미사용 입력, 출처/단위/제약 검사, 오류/보류가 정확 |
| reliability | 완주·복구·지연 | 10 | 정상 완료와 실패 표시 | 3회 반복과 timeout/429/잘못된 응답 복구, 중복 부작용 없음, 시간/호출 상한 확인 |
| ux | UI/UX·결과 이해 | 10 | 입력→결과 경로 동작 | 새 사용자가 설명 없이 핵심 작업, 근거 확인·실패 회복, 좁은 화면·키보드 검증 |
| reproducibility | 재현·운영·통합 | 10 | 실행 명령·버전·결과 저장 | 새 환경에서 재현, 계약/설정/배포 확인, mock/replay/live 구분 |
| pitch | 차별점·데모 전달 | 5 | 문제→실행→결과 이야기 | 지정 시간 내 핵심 가치/비교/한계 시연, 질문 대응·실패 대안 리허설 |

3점은 2점과 4점 사이의 증거가 있어야 한다. 예: UX에서 상태/좁은 화면 검사 기록은 있지만 새 사용자 시험이 없으면 3점. 증거 없이 기대만으로 3점을 주지 않는다. 과거 기록으로 매긴 점수는 `historical`로 표시하고 live 검증으로 바꾸지 않는다.

## 총점보다 먼저 보는 관문

| ID | pass의 조건 |
|---|---|
| mission_rules | 당일 미션·필수 NVIDIA 사용·반입·제출 조건을 확인하고 준수 |
| live_path | 실제 핵심 입력→모델/도구→검증→산출물 한 경로 완료 |
| evidence_integrity | 자료 부족/오류를 성공으로 꾸미지 않으며 출처/값/단위 검증 |
| failure_handling | timeout/불가능 입력에도 무한 대기·중복 실행 없이 종료/보류 |
| submission | 제출물 접근·실행 방법·마감·발표 조건 확인 |

값은 pass/fail/unknown. fail 또는 unknown이 하나라도 있으면 점수가 높아도 준비 완료가 아니다.
내부 운용 목표는 **80점 이상 + 모든 관문 pass + 미채점 없음**. 공식 통과선/우승 확률이 아니다. 이 기준으로 좋은 아이디어를 너무 일찍 폐기하지 말고, 미충족 항목을 다음 행동으로 변환한다.

## 짧은 반복

목표 정의 → 실제 핵심 경로 → 변화·실패 검증 → 근거 채점 → 필요한 개선 → 재채점. 작업 운영은 [2인 개발·로컬 시연](../operations/workflow.md)을 따른다.
항목마다 `입력/기대/관측/실행 모드/근거 경로/실패 시 다음 조치`를 남긴다. LLM 자기 평가만으로 정확성 점수를 올리지 않는다.

[빈 채점표](templates/scorecard.json)를 복사해 `python3 scripts/score.py 경로.json`으로 집계한다. 채점기는 사람이 입력한 증거의 진위를 보증하지 않는다.

## 대회 지향점과 가중치의 관계

문제 15·agent 판단 20·NVIDIA 활용 15의 50점은 공식 행사의 산업 문제/목표·도구/기술 활용 지향점을 구현 우선순위로 바꾼 팀 제안이다. 나머지 정확성·안정성·UX·재현·전달 50점은 결과를 검증하고 심사자가 확인하도록 하는 내부 기준이며 공식 독립 배점으로 확인된 항목은 아니다.

선정 요인과 실제 득점을 같게 보지 않는다. Bio-3의 73.75점은 설명용 잠정 채점이지 합격 점수의 추정치가 아니다. [추가 조사](bio3-review.md)와 [루브릭 채점 절차](scoring-guide.md)를 따른다.
