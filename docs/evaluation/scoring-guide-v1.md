# 루브릭 채점과 다음 개선 결정

공식 배점이 확인되지 않은 상태의 **내부 개발 기준**이다. 점수는 입상 확률이나 일반 성능 추정치가 아니다. 가중치/등급/관문 원본은 [rubric.md](rubric.md), 숫자 원본은 [rubric.json](rubric.json)이다.

## 1. 아이디어와 구현을 다르게 평가

설계 단계에서는 사용자·실패 상태·자료 접근·성공 검사 방법을 정한다. [미션 카드](../playbooks/templates/mission.md)에 해당 조건이 없으면 범위를 줄인다. 아직 구현하지 않은 계획을 실행 점수로 주지 않는다.
실제 결과가 나온 뒤에만 아래 항목을 채점한다. 기획의 예상 점수와 관측된 점수를 같은 표의 숫자로 섞지 않는다.

## 2. 8항목에 증거를 붙이기

| 항목 / 배점 | 확인 질문 | 최소 관찰 증거 | 4점까지 가려면 필요한 추가 증거 |
|---|---|---|---|
| 문제·미션 / 15 | 누구의 어떤 결정을 끝내는가? | 대표 입력, 결과물, 성공/실패 판정 | 사용자 확인과 측정 가능한 완료 기준·미션 조건 충족 |
| agent 판단 / 20 | 입력/관측이 바뀌면 어떤 행동이 달라지는가? | 정상+변화 입력의 다른 도구/추가 수집 경로 | 여러 분기·재계획·종료의 타당성과 단순 기준선 대비 이득 |
| NVIDIA 기여 / 15 | 이 구현에서 해당 구성요소가 실제 무엇을 했는가? | model/tool ID, 실제 호출 trace, 소비된 결과 | 필수 역할과 선택 이유·버전을 근거로 설명; 스킬은 선택한 경우 실제 적용 지점 표시 |
| 정확성·근거 / 15 | 틀렸다는 것을 어떻게 알아내는가? | 원문/수치/제약의 독립 validator | 고정 평가셋과 개발에 쓰지 않은 입력, 보류·오류 정답 확인 |
| 안정성 / 10 | 실패해도 제한 시간 안에 끝나는가? | timeout/429/빈 응답 중 해당 실패 1개 | 3회 반복, 상한, 부분 결과, 중복 부작용 방지 |
| UX / 10 | 처음 보는 사람이 결과와 다음 행동을 아는가? | 입력→진행→결과→근거, 실패 메시지 | 설명 없는 팀원 과업, 회복 행동, 화면/키보드 검사 |
| 재현 / 10 | 다른 팀원이 같은 절차로 실행하는가? | 명령·설정·버전·원본 입력/결과 | 새 환경 재현, 계약/배포 확인, mock/replay/live 구분 |
| 전달 / 5 | 짧게 문제·판단·결과·한계를 보여주는가? | 한 번의 완결된 시연 흐름 | 지정 시간 리허설, 기준선/차별점·질문 대응·장애 대안 |

공통 등급은 0=없음/실패, 1=설계·시안, 2=대표 1건/부분 증거, 3=정상+변화/실패 근거, 4=항목별 최고 조건 충족이다. 3점은 어떤 변화/실패 사례를 확인했는지 적어야 한다. 미실행/확인 불가는 null이다.
점수 = 각 배점 × 등급/4의 합. 코드 테스트 수나 API 응답 HTTP 200만으로 여러 항목에 고득점을 주지 않는다. 같은 trace를 여러 항목에 쓰려면 각 항목이 검사하는 서로 다른 사실을 적는다.

## 3. 점수보다 먼저 통과해야 하는 관문

미션/규정, 실제 핵심 경로, 근거 무결성, 실패 처리, 제출 접근을 모두 pass로 확인한다. unknown/fail이 하나라도 있으면 '준비 완료'가 아니다. 예를 들어 정상 데모가 예뻐도 예측 파일이 잘못된 입력의 캐시라면 점수보다 그 오류를 먼저 고친다.
80점은 내부 운용 목표일 뿐이며 정당한 보류를 성공처럼 포장해서 목표를 맞추지 않는다. 모델이 항상 보류해도 안전하다는 이유만으로 품질 만점을 주지 않는다.

## 4. 어떤 수정을 먼저 할까

관문 실패 → 핵심 결과 오류 → 미션/agent/NVIDIA 역할의 빈 근거 → 지연/UX → 부가 기능 순으로 고른다. 예상 점수 증가와 남은 시간은 계획 참고이며 실행 전 확보 점수로 세지 않는다.

예: 대표 입력만 돌아 agent 판단이 2/4라면, 변화 입력에서 다른 경로를 선택하고 결과를 검증해 3/4의 근거를 확보할 때 배점 20의 **5점**을 더 얻을 수 있다. 반면 장식만 바꾼 화면은 UX의 새 관찰 근거가 없어 점수가 오르지 않는다.

채점표는 [빈 양식](templates/scorecard.json)을 새 파일로 복사하고 `python3 scripts/score.py 경로.json`으로 계산한다. 미션 공개 후 공식 항목/배점이 주어지면 별도 버전으로 반영한다.
