# 에이전트 루브릭 — agent-v2

내부 개발 개선용 100점. 공식 심사 배점이 아니다. 숫자·등급 원본은 [agent-rubric.json](agent-rubric.json)이며 [공통 채점 방법](scoring-guide.md)을 적용한다.

각 등급의 모든 조건을 만족해야 한다. 0=검사로 핵심 동작 실패/부재 확인, 1=설계/정적 구현만 확인, null=미검증. 3·4는 이전 등급 조건도 충족해야 하며 혼합된 증거에서는 충족한 가장 낮은 등급을 쓴다.

| ID / 배점 | 2: 대표 실행 | 3: 변화·실패 검증 | 4: 독립·반복 검증 |
|---|---|---|---|
| goal · 과업·완료 기준 / 15 | 대표 입력에서 요구 산출물과 완료/보류 조건 확인 | 정상·변화·불가능 입력의 기대 결과를 실행 전 정의하고 관측과 대조 | 미사용 입력에서도 과업 성공률·정당한 보류·잘못된 완료를 각각 검산 |
| agency · 관측 기반 선택·기준선 대비 가치 / 25 | 실제 모델 선택과 도구 실행 한 경로를 분리해 확인 | 관측 변화에 따라 선택/추가 수집/종료가 달라지고 선택 이유가 결과와 연결 | 같은 입력·예산의 직접 호출/규칙 기준선과 비교해 품질·사용자 부담·비용 중 이득을 측정; 손해도 공개 |
| correctness · 결과 정확성·근거 검증 / 20 | 대표 결과를 독립 검사기로 검산하고 출처와 연결 | 정상·누락·충돌·잘못된 도구 응답을 검사하고 잘못된 완료와 과도한 보류를 구분 | 미사용 사례를 포함한 고정 평가셋에서 출력 정답·근거·단위/제약을 독립 검증; 모든 보류로 점수 회피하지 않음 |
| reliability · 종료·복구·중복 방지 / 15 | 정상 종료와 한 실패 경로를 확인 | timeout·유효하지 않은 출력 등 해당 실패를 주입하고 제한된 재시도·부분 결과·종료 뒤 추가 호출 방지 확인 | 대표 입력 반복 3회와 실패 재실행에서 종료·복구·중복 부작용 방지 유지; 실패 시도도 분모에 포함 |
| efficiency · 호출·시간·비용 제어 / 10 | 실제 요청 수·소요 시간과 설정 상한을 기록 | 재시도를 포함한 실제 요청·단계·출력/일일 예산을 런타임에서 차단; 캐시/중복 호출 구분 | 동일 평가셋의 성공당 요청·시간·비용을 기준선과 비교; 품질을 낮추지 않고 합의한 한도 충족 |
| nvidia · NVIDIA 구성요소의 실질 기여 / 10 | 핵심 경로에서 실제 NVIDIA 모델/도구 응답이 사용됨을 추적 | 버전·입출력·역할을 기록하고 모델 선택과 코드 실행의 책임을 구분 | 해당 구성요소의 제거/대체 비교 또는 기술적 필수 제약으로 기여를 검증; 설치/로고/스킬 수로 대체하지 않음 |
| boundaries · 입력·권한·신뢰 경계 / 5 | 형식 오류와 허용하지 않은 행동을 거부 | 외부 자료의 지시문·허용하지 않은 도구/인자·비밀값 노출을 테스트하고 코드로 차단 | 미사용 공격/혼합 입력에서도 권한 범위를 지키며 정상 과업을 불필요하게 막지 않음 |

## 필수 관문

| ID | pass 조건 |
|---|---|
| outcome_integrity | 확정 결과가 독립 검사와 일치하며 근거 부족/실패를 성공으로 만들지 않음 |
| bounded_execution | 호출·재시도·시간/단계 상한과 종료 뒤 무호출 확인 |
| action_boundary | 허용 도구/인자/권한만 실행하며 비밀값을 출력하지 않음 |

영역 완료는 80점 이상, 모든 항목 3 이상, 미채점 없음, 영역 관문 모두 pass다. 다른 영역의 높은 점수로 상쇄하지 않는다. 전체 서비스의 준비 여부는 [공통 통합](integration.md)에서 별도로 확인한다.

## 경계

프런트 외관·모션·발표는 채점하지 않는다. mock 규칙의 분기를 모델 자율성으로, 도구의 HTTP 성공을 업무 정답으로 바꾸지 않는다. NVIDIA 항목은 실제 기여를 확인하며 공식 행사 요구 충족 여부는 통합의 event_rules에서 확인한다. 기준선 대비 이득이 확인되지 않으면 agency 4를 부여하지 않는다.
