# 프런트 루브릭 — frontend-v2

내부 개발 개선용 100점. 공식 심사 배점이 아니다. 숫자·등급 원본은 [frontend-rubric.json](frontend-rubric.json)이며 [공통 채점 방법](scoring-guide.md)을 적용한다.

각 등급의 모든 조건을 만족해야 한다. 0=검사로 핵심 동작 실패/부재 확인, 1=설계/정적 구현만 확인, null=미검증. 3·4는 이전 등급 조건도 충족해야 하며 혼합된 증거에서는 충족한 가장 낮은 등급을 쓴다.

| ID / 배점 | 2: 대표 실행 | 3: 변화·실패 검증 | 4: 독립·반복 검증 |

## 필수 관문

| ID | pass 조건 |
|---|---|
| truthful_state | 입력/후보/실행 ID가 이벤트와 일치하고 거짓 호출·완료가 없음 |
| critical_access | 핵심 과업을 키보드로 완료하고 초점 함정/조작 불가가 없음 |
| recoverable_ui | 실패·새 실행에 낡은 결과/타이머가 섞이지 않으며 복구 행동이 실제 지원됨 |

영역 완료는 80점 이상, 모든 항목 3 이상, 미채점 없음, 영역 관문 모두 pass다. 다른 영역의 높은 점수로 상쇄하지 않는다. 전체 서비스의 준비 여부는 [공통 통합](integration.md)에서 별도로 확인한다.

## 경계

모델의 정확도를 프런트에 재채점하지 않는다. UI는 올바른 계약을 올바르게 표시하는지 본다. fixture로 브라우저 동작을 충분히 관측하면 영역 점수는 받을 수 있지만 live 통합을 통과한 것은 아니다. 데이터에서 유도되는 디자인 규칙은 [시각 규칙](../../.agents/skills/nvidia-ui/references/activity-rules.md)을 사용한다.

WCAG 2.2의 키보드·초점·명암 대비·상태 메시지 항목을 선정해 검사한다. 2.3.3 모션 감소는 AAA이며 프로젝트가 선택한 요구다. 제한된 데스크톱 평가를 WCAG 전체 준수 인증이나 모바일 검증으로 표현하지 않는다. 성능은 UI 응답을 측정하고 모델 대기 시간과 분리한다.
