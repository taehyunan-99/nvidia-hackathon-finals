# 2인 개발·로컬 시연 운영

본선은 사용자와 팀원 총 2명이 진행하며 미션은 당일 공개된다. 개발과 리허설은 본선 저장소에서 진행하고, 예선 프로젝트는 필요한 구현·디자인·실측 근거의 참고자료로 사용한다.

## 확정한 디자인

디자인 준비는 사용자와 확정했다. [80개 세부 기준과 상태 표시 묶음](../design/design-decisions.json)을 [디자인 스킬](../../.agents/skills/nvidia-ui/SKILL.md)·토큰·공통 컴포넌트 CSS·[대표 화면](../../design/playground.html)으로 재사용한다. 데스크톱 전용이며 모바일은 범위에서 제외한다.

진행·완료는 녹색, 보류는 황갈색, 실패는 빨강, 입력 전은 회색으로 표시하고 아이콘·설명·다음 행동을 함께 제공한다. 완료는 검증된 범위에만 사용하고 보류에서는 확인한 결과를 유지한다. `mock/replay/live`와 미검증을 구분한다.

미세 색상·간격 비교는 종료한다. 글꼴 제공 방식·표 장식·페이지 구조·다크 테마 등 미정값은 [디자인 안내](../design/README.md)에 구분하며 사용자 요청이나 실제 구현 필요 없이 다시 논의하지 않는다. 대표 화면은 주제·기능·배치 확정이나 실제 에이전트 실행 근거가 아니다.

## 합의한 진행 방향

두 사람의 개인 정보·강점 인터뷰와 개인별 담당 확정은 이번 준비 범위에서 제외한다. 미션 해석과 최소 end-to-end 연결을 함께 진행한 뒤, **에이전트 설계·구현**과 **프런트·서비스 연결**의 두 영역으로 나눈다. 한 명을 상시 검증 전담으로 고정하지 않고 서로의 구현을 교차 확인한다.

현재 계획은 실제 배포 없이 **로컬 실행·시연**을 목표로 한다. 호스팅·도메인·공개 서비스 운영은 준비 범위에 넣지 않는다. 로컬 실행에서도 실제 모델·도구 호출과 결과 검증은 필요하며, mock/replay를 live 성공으로 대체하지 않는다. 공식 제출 조건은 아직 미확정이므로 온보딩에서 배포나 외부 접근이 필수인지 확인되면 범위를 다시 논의한다.

| 영역 | 맡을 범위 | 완료 기준의 방향 |
|---|---|---|
| 공동 시작 | 미션 해석·최소 산출물 선택·입출력/상태 계약·최소 경로 연결 | 실제 입력→에이전트의 도구 선택→실행→검증→결과 1건 완주 |
| 에이전트 설계·구현 | 관측 상태·허용 도구·선택/종료 판단·반환값 검증·실패/보류 처리 | 상태 변화에 맞는 행동과 검증 결과를 서비스에 전달 |
| 프런트·서비스 연결 | 입력·로컬 호출 경로·실행 상태·결과/근거 표시·시연 흐름 | 확정 디자인을 재사용해 입력부터 결과·실패 후 다음 행동까지 연결 |
| 공동 마무리 | 수시 통합·동료 교차 검증·실행 방법 정리·발표/제출 준비 | 합쳐진 로컬 서비스의 핵심 흐름과 한계를 두 사람이 확인 |

두 구현 영역은 최소 연결 이후 병렬 진행할 수 있다. 서비스 연결은 화면만이 아니라 에이전트를 호출하고 결과를 받는 경계까지 포함한다. 구체적인 계약·통합 담당·발표 담당은 당일 미션에 맞춰 정하며 개인에게 미리 배정하지 않는다.

## 유지할 기준

- 모델 호출은 [본선 공통 기본값](../playbooks/model-policy.md)을 재사용한다.
- 에이전트는 목표와 관측 상태에 따라 도구를 선택하고, 코드 검증기가 결과와 종료 조건을 확인한다.
- [승인된 루브릭](../evaluation/README.md)의 항목·가중치는 유지한다. 반복 평가는 `$agent-rubric`과 `$frontend-rubric`을 영역별로 사용한다.
- CI는 로컬 자동 검사+동료 검증+경량 원격 CI 보조가 기본 방향이다. 마지막 유효 검증 이후 누적 변경을 검사하며, 10분 초과는 일괄 차단 대신 검증 불충분과 대체 확인으로 처리한다.
- both 가이드·repo 스킬 구조를 유지하고, 별도 작업 완료 보고서를 만들지 않는다.

## 구현 단계에서 확인할 조건

본선 반입/필수 기술/제출 규정, 실제 모델 권한·GPU 환경, 두 사람의 노트북 환경은 확정 정보가 필요하다. 실제 API 연결과 새 미션의 end-to-end 검증, CI의 검사 목록·성능 측정은 문서 준비만으로 완료되지 않는다.

개인별 정보 수집을 준비 논의의 선행 조건으로 삼지 않는다. 위의 진행 방향을 유지하고, 실제 구현 시 두 영역의 계약·로컬 실행 환경·통합 책임과 미션별 완료 조건을 정한다. CI의 실제 검사 항목과 시간은 구현 후 측정한다.


## 미확정 조건과 참고안

공식 반입·필수 기술·자원·제출·발표 조건은 [행사 안내](event.md)에서 확인한다. 개인별 담당과 미션별 완료 조건은 아직 확정하지 않았다.
