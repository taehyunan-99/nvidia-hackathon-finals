# 두루(Duru) 프런트

React·TypeScript·Vite 데스크톱 프로토타입. [제품 요구사항](../docs/PRD.md)과 [NVIDIA UI 기준](../.agents/skills/nvidia-ui/SKILL.md)을 사용한다. 이 디렉터리 외의 기존 디자인 자산을 직접 참조하므로 저장소 전체를 체크아웃한다.

## 실행

Node.js 22.18 이상(첫 구현 검증: 25.8.1)에서 이 디렉터리를 작업 디렉터리로 사용한다.

```sh
npm ci
npm run dev
```

기본 주소는 http://127.0.0.1:5173 이다. 로컬 미리보기이며 공개 배포가 아니다. 빌드 결과는 `dist/`에 생성된다.

공개 프런트: [두루](https://d25wpps17lj0dn.cloudfront.net/). Docker와 기존 AWS를 통한 배포·복구 방법은 [수동 배포](../docs/playbooks/frontend-deployment.md)를 따른다. 현재 예시 데이터 화면이며 실제 에이전트 연결은 별도다.

```sh
npm run build
npm test
npx playwright install chromium
npm run test:browser
```

빌드는 타입 검사도 포함한다. 브라우저 검사는 개발 서버가 없으면 자동 기동한다. 계약·조건 판정은 Node 테스트, 화면 왕복·추가 질문·비교·빈 결과·실패·보안 표시·키보드는 Playwright로 확인한다. 1024/1440px 데스크톱을 대상으로 하며 모바일은 범위 밖이다.

## 사용자 흐름

관심 분야 → 자녀 학년·보호자 → 날짜·지역 → 분석 → 필요한 추가 질문 → 후보·근거 비교. 결과에서 조건을 수정하면 기존 실행·비교 선택은 지우고 조건 선택값을 유지한다. 팀원 탭 왕복은 현재 탐색을 유지한다. `/?demo=1`로 접속한 뒤 입력 하단의 ‘화면 검증용 예시 설정’에서 자료 충돌·빈 결과·조회 실패·정책 거부·한도 종료를 선택한다.

모든 프로그램·장소·가격·일정·근거는 합성 예시다. 2026년 10월 날짜 카드는 화면 검증용이며 실제 운영일 또는 라이브 날짜 선택 계약이 아니다. 관심 분야·지역·학년 구분과 후보 배열 순서는 임시 화면 계약이며 추천 순위·고정 후보 개수를 확정하지 않는다. 미취학/중고등 연령 구분은 실제 프로그램의 나이별 제한을 판정할 만큼 세밀하지 않아 실제 연동 시 생산자와 다시 맞춰야 한다.

현재 런타임 스킬 실행이나 모델 호출은 없다. mock 어댑터의 관측별 규칙이 후보 조회·상세 근거 조회·조건 검증을 선택한다. 재생 시간은 표현용이며 실제 소요 시간이나 진행률이 아니다. 일시정지는 예시 재생만 정지한다. 공식 신청 URL이 없으므로 신청 버튼은 비활성이다.

## 파일과 연결 경계

| 파일              | 역할                                             |
| ----------------- | ------------------------------------------------ |
| `src/contract.ts` | 프런트 임시 입력·후보·근거·판정·실행 이벤트 타입 |
| `src/mock.ts`     | 합성 데이터와 조건별 조회·질문·보류·실패 어댑터  |
| `src/App.tsx`     | 입력·분석·비교·팀원·접이식 보안 기록             |
| `src/styles.css`  | 확정 토큰 위의 서비스 화면 배치                  |
| `tests/`          | 조건 변경·미확인 보존·화면 흐름 검사             |

공통 CSS와 `renderActivity`·`renderFlow`, 팀원 정보는 기존 스킬 자산을 직접 재사용한다. 팀원 본선 역할·기여·개인 링크가 없으면 표시하지 않는다. 확인된 현재 Git 원격 주소는 `App.tsx`의 단일 `repository` 상수로 두 메뉴에 연결한다.

라이브 연결 전 백엔드와 필드·정책·에러 의미를 합의하고 외부 응답의 런타임 검증 어댑터를 추가해야 한다. TypeScript 타입만으로 외부 응답을 검증했다고 간주하지 않는다. 요청 ID·조건 버전·이벤트 순번으로 이전 실행/역순/중복 이벤트를 배제하고, 후보의 출처·조회 시점·공식 링크를 검증한 뒤 연결한다. 실데이터가 없는 경우 mock으로 조용히 대체하지 않는다.

실제 Nemotron/NIM·NAT·API·OpenShell·익명 작업 소유권·모델 호출 예산·공통 테스트 CLI는 이 프런트에 구현되어 있지 않다. 보안 접이식 기록의 ‘정책 거부’도 합성 사례이며 정책 집행 증거가 아니다. 팀원 이미지·GitHub 링크를 제외하면 프런트는 외부 서비스를 호출하지 않는다. API 키를 프런트 환경변수나 번들에 넣지 않는다.

첫 화면은 예선의 짧은 소개·선택 카드·진행 버튼 구성을 따른다. 프로젝트 아이콘은 `public/duru-icon.svg`이며 두 개의 둥근 고리로 가족과 문화체험의 연결을 표현한다. 헤더와 파비콘이 같은 원본을 사용한다. mock 구분과 근거·보안 검증 상태는 분석·결과에서 유지한다.

전체 화면의 왼쪽 메뉴는 제거하고 분석·추가 질문·결과의 진행 단계는 상단에 표시한다. 분석 화면은 현재 관측·도구 지도·재생 및 결과 이동만 표시한다. 추가 조건 질문은 분석 하단에 누적하지 않고 별도 화면으로 전환한다. 상세 실행 기록과 보안 기록은 결과에서 확인한다.

도구 지도는 예선의 노드 경계 간 연결 방식을 유지하며, 이름·상태는 중앙 연결선 반대편에 배치한다. 상단 도구는 원 위, 하단 도구는 원 아래에 표시하고 후보 링 크기를 포함한 여백을 확보한다. 긴 문구가 SVG 바깥으로 잘리지 않도록 실제 텍스트 경계로 viewBox를 확장한다. 도구·후보·상태 문구를 추가할 때 선과 텍스트의 교차·잘림을 데스크톱에서 함께 검증한다.

사이트명·체험 찾기는 항상 입력 첫 단계로 이동하고 선택값을 유지한다. 현재 탭에서의 분석은 일시정지해 보존하고 ‘이전 분석 보기’로 돌아갈 수 있다. 새 실행·결과의 조건 수정은 기존 분석을 교체한다. 입력 선택값만 sessionStorage에 보관해 같은 탭 새로고침에도 유지하며, 새 탭·탭 종료 이후의 검색 이력 복원은 제공하지 않는다. 브라우저의 자체 세션 복원 정책에 따라 닫힌 탭 복원 시 값이 복구될 수 있다.
